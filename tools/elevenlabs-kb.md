## AI agent build: Career Ops job-search pipeline

George runs his own job search on a pipeline of Claude Code agents with a fact gate on every output.

George first designed a three-stage agent team: a Gmail digest reader, a job qualifier that scores each posting, and a resume customizer for everything above a threshold. It had strict source rules: one trusted feed, no outside enrichment, and no claim that is not in the resume.

George then migrated that process onto Career Ops, an open-source job-search agent. Career Ops was originally created by Santiago Fernández and a contributor community. George has extended it by merging his own resume maker into it. His other work on top of it is his targeting profile, scoring overrides, house rules, a few helper scripts, and the review discipline.

Career Ops is local-first and runs inside AI coding command-line tools such as Claude Code, Codex and OpenCode. It discovers jobs through more than 130 applicant-tracking-system and job-board provider modules, verifies that a posting is still live, evaluates fit with a structured assessment and a 1 to 5 score, and drafts tailored resumes and cover letters. It never submits an application. Forms are pre-filled and then the tool stops so the human reviews and submits.

George operates it interactively only. Every generated document is reviewed before it leaves his machine, and a claim that does not trace to his source resume is cut.

Authorship: George designed the three-stage pipeline, its source and fact rules, and his Career Ops profile and house rules, and extended Career Ops by merging his resume maker into it. Agents wrote the pipeline stages, the scorer and his customizations.

The Career Ops project is on GitHub at github.com/santifer/career-ops.

## AI agent build: Jarvis voice assistant

Jarvis is a local voice assistant George built in 2026. It listens for the wake word "hey Jarvis", transcribes speech on the machine, answers through a Claude model with a registry of tools, and speaks the reply while it is still being generated.

What makes Jarvis different is that it does real work. For anything that touches the file system or a shell, Jarvis hands the task to Claude Code running in headless mode and reads the result back in one to three sentences.

Jarvis can manage Google Calendar, Gmail across several accounts, and contacts by voice. It can get weather, traffic-aware directions, local business search and web research. It controls a household to-do board that runs on a Raspberry Pi. It has a phone client, a progressive web app that continues the same conversation that started at the desk. It has long-term memory.

The technology in Jarvis includes Python, the Claude API, faster-whisper for speech-to-text, Silero voice activity detection, Piper text-to-speech, openWakeWord, FastAPI and Google Workspace APIs.

A notable safety decision in Jarvis: a delegated task may read anything and write almost anywhere, but Jarvis's own tool registry, orchestrator, voice pipeline and memory are protected paths unless an explicit builder mode is engaged. So it cannot quietly rewrite itself, and builds can be reverted with one command.

Authorship: George designed the overall system and feature set, researched and selected the speech stack, and did quality assurance on every build. Agents wrote essentially all of the code.

## AI agent build: TraderIO order router

TraderIO is a webhook-to-broker order router George built in 2026. It receives TradingView strategy alerts over a webhook, filters them with declarative rules, chooses which of several prop-firm futures accounts should take the trade, and places a protected order through NinjaTrader.

The design centers on five independent safety gates that an order must pass: the router's dry-run default, the filter rules, rotation eligibility, an account allowlist inside the NinjaTrader add-on, and the add-on's own dry-run. Two of those gates live inside NinjaTrader where the service cannot change them, on purpose. The design assumes any single component can be wrong.

TraderIO picks an account in two layers. Hard gates remove ineligible accounts, then a weighted score ranks the rest. The scoring code is pure, does no input or output, and is fully unit-tested. The project has 765 tests.

TraderIO receives alerts through a Cloudflare tunnel that publishes exactly one path, the webhook. The dashboard and other pages are refused at the edge. It runs around the clock as an auto-restarting Windows service and has done so since mid-2026. It replaced an earlier n8n flow and then a hosted relay service.

TraderIO is built with Python 3.12, FastAPI, C# NinjaScript for NinjaTrader 8, Cloudflare Tunnel, and the Google Sheets and Gmail APIs for audit logs and a daily recap.

Authorship: George designed the signal path, the gate model, the rotation rules and the operating procedures. He ran it live and turned every incident into a documented rule. Agents wrote the Python service, the two NinjaScript add-ons, the dashboard and the tests.

TraderIO is a private project. No account data or trading results are shared on the site, and the assistant has none. The assistant does not give trading or financial advice.

## AI agent build: LandFinder land pipeline

LandFinder is a pipeline George built in 2026 that finds land and acquisition opportunities in Walker County, Georgia: tax sales, sheriff sales, estate and probate notices, vacant rural acreage and absentee owners. Public records go in, and a weekly, reviewable, ranked lead list comes out in CSV and Excel.

The key design idea in LandFinder is that the language model is used for reading, never for deciding. Claude extracts fields from legal notices, with a confidence value. Scoring, matching and redemption-date arithmetic are deterministic Python with unit tests.

LandFinder has seven stages: ingest, parse, enrich, match, score, report and alert. The model is called in exactly one stage, parse.

Legal guardrails are designed into LandFinder. Every scraper throttles and identifies itself. The legal-notice portal is queried for one county only. Notice content is never redistributed. Parcel data is purchased under licence rather than scraped. Deed checks are left to a person.

LandFinder is built with Python 3.12, PostgreSQL with PostGIS, the Claude API, Playwright, pdfplumber and Tesseract OCR.

Authorship: George designed the pipeline stages, the data-source choices, the legal guardrails, and the decision to keep the model out of scoring. Agents wrote the scrapers, parsers, the PostGIS enrichment, scoring and the weekly report.

LandFinder is a private project.
